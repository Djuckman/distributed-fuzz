# Architecture Decision Records

ADR фиксируют значимые технологические решения и их связь с архитектурными контрактами. Нормативным источником domain model, lifecycle и инвариантов остаётся [Architecture.md](../../Architecture.md), а технологическое отображение описывается в [Implementation.md](../../Implementation.md).

## Статусы

- `PROPOSED` — решение предложено и ожидает рассмотрения.
- `ACCEPTED` — решение принято для реализации.
- `SUPERSEDED` — решение заменено более новым ADR.
- `REJECTED` — решение рассмотрено и отклонено.

ADR выбирает реализацию порта, но не вводит новые domain entities или lifecycle transitions. Изменение архитектурного контракта выполняется отдельным изменением `Architecture.md` с соответствующим согласованием.
